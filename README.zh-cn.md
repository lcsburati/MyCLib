## 目的

**目的：** 该项目旨在通过模拟一些库来理解 C 语言的行为，基于我自己的理解。目标是使用我目前的知识达到类似的结果，专注于理解语言语法、数据结构等方面。目的是真正理解低级语言（在这里是 C）的工作原理，理解幕后发生的抽象。此外，我想加深我的知识并练习逻辑推理，以改进我解决问题的方式。

## 如何编译 (CMake)

您可以使用 **CMake** 编译项目：

```bash
mkdir build && cd build
cmake ..
make
./main
```

## 函数

### string_utils.h

> 这里的目标是存储原型、结构和常量，以保持 source string_utils.c 更简洁。

* `#define OFFSET ('a' - 'A')`：定义小写和大写之间距离的常量（`32`）。用于 my_tolower 和 my_toupper。

* `#define STR_BUFFER 256`：定义字符串可以拥有的最大字符大小。

* 注意：选择 #define 而不是 const 是由于变量的简单性，因为在运行时类型不会很重要。

* `typedef char * string`：为 char* 定义别名。我们可以直接使用指针工作，但为了便于理解字符串在底层的工作原理，我选择使用 string 作为 char* 的别名。（我理解在 C 中将指针隐藏在 typedef 中不是好的做法，但这种情况下只是为了确保理解字符串天然就是指针）。

<details>
<summary><strong>my_strlen</strong> (点击展开)</summary>

在这个函数中，输入参数是 `string` 类型（`char*` — 指向 `char` 的指针）。  
函数的返回类型是 `size_t`，选择它是为了方便与 unsigned int 的大小相关的可移植性，因为我们处理的是数组（字符串）的大小。

我们首先定义将计算字符串（数组）长度的变量，这里命名为 `length`，也是 `size_t` 类型，原因与函数返回值相同（另外，它恰好是返回的值）。

从那里开始的逻辑很简单：知道C中的每个字符串都以空字符 `\0` 结尾，我们可以遍历字符串直到找到它。这个字符被解释为 `0` 或 `false`（因为布尔值在C中不是原生存在的），所以我们可以简单地使用 `while (*str)` 来指示程序它应该遍历从输入字符串开始的指针，直到找到 `\0`。每次循环迭代，我们将 `length` 增加1，累积字符串大小。

**无效输入和 overflow 检查：** 函数检查字符串是否为 `NULL`；如果是，则立即返回 `0`。此外，如果在迭代过程中长度达到或超过 `STR_BUFFER`，函数返回 `STR_BUFFER + 1`。这样做是为了把错误/overflow 和正常计数区分开来，因为返回 `0` 也可能表示空字符串。这里的 `+ 1` 可以处理边界情况，也能让依赖 `my_strlen` 的函数更明确地知道这个长度已经超过预期限制。

**注意：** 函数也将空格（` `）识别为一个字符。也就是说，如果您传递带有空格的字符串，返回的大小将是字符串的总大小，包括空格。我认为重要的是要提到这一点，因为根据上下文，一些函数/方法将空格视为分隔符，最终会"忽略"这个字符（例如，使用 `scanf("%s")` 读取输入时）。

<summary><strong>my_toupper</strong> (点击展开)</summary>

在这个函数中，输入参数是一个字符串（char指针），命名为 `str`。

我们首先定义处理所需的变量：`length`（`size_t`）和 `result`。对于 `result`，我们通过 `malloc` 函数在*堆*上分配内存，创建一个指针，标记一个块的开始，块的大小正好是输入字符串的大小 + 1字节空间用于空字符 `\0`。

分配后，我们验证 `malloc` 是否成功；否则，函数返回 `NULL`（防止如果内存中没有连续空间进行块分配时出现故障）。

我们还定义了一个辅助指针 `string current = result`。这允许我们遍历和填充新的内存块，而不丢失对块开头（`result`）的引用，这对于函数返回是必要的。

转换逻辑遍历输入字符串（`str`）：我们检查当前字符是否是小写字母；如果是，我们通过从字符的 ASCII 值减去 `OFFSET` 值（32）将其转换为大写。否则，我们只将原始字符复制到新块中。

在循环结束时，我们将 `current` 的最后一个字符设置为 `\0`，正确终止字符串。我们返回 `result`，它指向现在处于 **UPPERCASE** 的新字符串的开头。

**空输入或 buffer 限制检查：** 函数检查字符串长度是否为 `0` 或大于 `STR_BUFFER`；如果是，则返回 `NULL`，既可以避免不必要的内存分配，也可以阻止被 `my_strlen` 标记为 overflow 的字符串继续进入分配流程。

</details>

<summary><strong>my_tolower</strong> (点击展开)</summary>

在这个函数中，我们遵循与 `my_toupper` 相同的内存管理逻辑，使用输入指针 `str` 并使用 `malloc` 在*堆*上分配一个新块来存储结果。

根本区别在于转换逻辑：我们遍历输入字符串，检查当前字符是否是大写字母。如果是，我们通过将 `OFFSET` 值（32）添加到字符的 ASCII 值来将其转换为**小写**。

与其他函数一样，我们通过检查内存分配的成功与否来保持安全。在最后，我们确保字符串以空字符 `\0` 终止，并返回 `result` 指针，它指向转换为 **lowercase** 的新字符串的开头。

**空输入或 buffer 限制检查：** 函数检查字符串长度是否为 `0` 或大于 `STR_BUFFER`；如果是，则返回 `NULL`，既可以避免不必要的内存分配，也可以阻止被 `my_strlen` 标记为 overflow 的字符串继续进入分配流程。

</details>

<summary><strong>my_strcmp</strong> (点击展开)</summary>

输入参数是两个要比较的字符串：`str1` 和 `str2`。这里的目标是模拟 `strcmp` 的行为：如果两个字符串相等，函数返回 `0`；如果它们不同，返回值来自第一次发现不同字符时两个字符之间的差值。

首先，我们检查两个输入是否为空指针。如果 `str1` 或 `str2` 是 `NULL`，函数返回 `1`，表示这次比较不是相等的结果。

之后进入主要处理逻辑：只要两个字符串都还没有到达空字符 `\0`，循环就继续执行。在循环内部，我们比较 `str1` 当前指向的字符和 `str2` 当前指向的字符。如果它们不同，函数马上返回这两个字符的差值。如果它们相同，就通过 `str1++` 和 `str2++` 同时移动两个指针，继续比较下一组字符。

当循环结束时，函数会再返回一次当前两个字符的差值。这样可以覆盖其中一个字符串先结束的情况，例如 `"abc"` 和 `"ab"`：这时比较的就是 `'c'` 和 `'\0'`。

返回表达式中使用了到 `unsigned char` 的类型转换，因为这里把 `char` 放进整数运算中。不同编译器中普通的 `char` 可能被当成 signed 或 unsigned，这会影响基础 ASCII 之外的字符。转换成 `unsigned char` 后，比较结果会更稳定，也更接近 `strcmp` 预期的行为。

**返回码：**

- `0`：两个字符串相等。
- 负值：`str1` 中第一个不同字符小于 `str2` 中对应的字符。
- 正值：`str1` 中第一个不同字符大于 `str2` 中对应的字符。
- 初始检查中的 `1`：至少一个输入为 `NULL`。

</details>

<summary><strong>my_strcmp_percent</strong> (点击展开)</summary>

输入参数是 `str1` 和 `str2`，类似于 `my_strcmp`。主要区别在于算法：要计算相似度百分比，我们使用**莱文斯坦距离**，它根据将 `str2` 转换为 `str1` 所需的最少操作数填充矩阵——这些操作是：字符的**插入**、**替换**和**删除**。

算法首先使用 `my_strlen` 定义 `str1` 和 `str2` 的大小。因为 `my_strlen` 现在在检测到 overflow 时会返回 `STR_BUFFER + 1`，所以 `my_strcmp_percent` 会利用这个信息，在尝试用无效大小创建 Levenshtein 矩阵之前就先停止。

进入主要计算之前，函数会处理几个特殊返回值：如果任一输入为 `NULL`，返回 `-3`；如果任一字符串超过 `STR_BUFFER`，返回 `-2`；如果任意内存分配失败，返回 `-1`。

完成这些检查后，函数在堆上分配 `matrix`——作为双指针（`int**`）处理——使用 for 循环通过 `malloc` 为行和列分配空间。这里也增加了对中途分配失败的保护：如果某一列分配失败，函数会先释放之前已经申请到的空间，再返回错误，避免内存泄漏。

分配后的前两个循环定义**矩阵边框**：左边框（列0）和上边框（行0）填充递增的值，表示从零开始的成本——也就是说，如果其中一个字符串为空，需要多少操作。

在主循环（遍历行和列的两个嵌套循环）中，我们通过三元条件定义 `cost` 变量：如果比较的字符相等，`cost = 0`；否则，`cost = 1`。

然后，我们取**3个操作中的最小值**——因为我们想要到达结果的最小成本路径，因为可以用不同的方式将一个字符串转换为另一个字符串，但成本不同。每个操作由当前单元格的3个相邻单元之一表示：

- **`[i-1][j]` → 删除：** 我们只在一个方向（str1）前进，意思是那个字符应该被忽略——成本+1。
- **`[i][j-1]` → 插入：** 我们只在 str2 的方向前进，也就是说，我们比较的字符串缺少1个字符——成本+1。
- **`[i-1][j-1]` → 替换（或匹配）：** 我们在两个方向都后退一个，保持同步——如果字符不同成本+1，或者如果相同成本为0。

循环完成后，矩阵被完全填充，`matrix[str1_length][str2_length]` 中的值是所有操作的最终累积距离。

从这里，我们使用三元条件来识别哪个字符串更大，并使用其大小作为百分比计算的分母。如果两个字符串都是空的，这个分母会变成 `0`；这种情况下，函数会先释放矩阵，再返回 `-4`，避免除以零。最后，在正常流程中，我们释放分配的矩阵空间并以 `double` 形式返回相似度。

**返回码：**

- `0` 到 `100`：成功计算出的相似度百分比。
- `-1`：矩阵内存分配失败。
- `-2`：至少一个字符串超过 `STR_BUFFER`，表示 `my_strlen` 检测到了 overflow。
- `-3`：至少一个输入为 `NULL`。
- `-4`：两个字符串都为空，导致计算分母等于 `0`。

**关于空字符串的注意：** 因为空字符串不会超过 `STR_BUFFER`，一个空字符串和另一个有内容的字符串比较时，仍然可以进入计算流程，结果通常会是 `0%`。两个字符串都为空的情况会用 `-4` 单独处理，因为没有最大长度可以作为百分比计算的基础。

**注意：** 错误码现在使用负数，就是为了避免和有效百分比混在一起。因为正常返回值会保持在 `0` 到 `100` 之间，所以任何负数都表示函数在最终计算之前就停止了。

</details>
